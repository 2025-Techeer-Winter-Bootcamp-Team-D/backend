# 뉴스 크롤링 및 요약 시스템 구현 계획

## 개요

Naver 검색 API로 뉴스를 크롤링하고, jina.ai로 본문을 추출한 후:
- **본문**: 벡터 임베딩하여 **OpenSearch**에 저장 (의미 기반 검색용)
- **요약문**: Gemini API로 생성하여 **PostgreSQL**에 저장 (기본 정보와 함께)

**핵심 기술:**
- Django 6.0 + DRF
- Celery (비동기 작업 처리)
- Redis (Message Broker)
- Naver 검색 API (뉴스 검색)
- jina.ai (본문 추출)
- Gemini API (요약 생성 + 벡터 임베딩)
- **DBSCAN 클러스터링 (중복 뉴스 제거)**
- **OpenSearch (벡터 검색 엔진)**
- PostgreSQL (메타데이터 저장)

## 아키텍처

```
[사용자] → POST /news/crawl-jobs/crawl/
              ↓
         [Django API]
              ↓
    [CrawlJob 생성 + Celery Task 실행]
              ↓
         [Redis Broker]
              ↓
       [Celery Worker]
              ↓
    [Naver API] → [뉴스 검색]
              ↓
       [jina.ai] → [본문 추출]
              ↓
    [RefineService] → [본문 정제 (Trafilatura + Gemini)]
              ↓
         ┌────┴────┐
         ↓         ↓
    [Gemini]  [Gemini Embedding]
         ↓         ↓
    [요약 생성] [벡터 변환]
         ↓         ↓
   [PostgreSQL] [임베딩 수집]
   (News 테이블)      ↓
                 [DBSCAN 클러스터링]
                      ↓
              [중복 제거 (대표 기사 선택)]
                      ↓
                 [OpenSearch]
                 (벡터 인덱스)
```

**데이터 흐름:**
1. Naver API로 뉴스 메타데이터 수집
2. jina.ai로 전체 본문 추출
3. RefineService로 본문 정제 (Trafilatura 1차 + Gemini 2차)
4. **병렬 처리**:
   - Gemini로 요약 → PostgreSQL (title, url, summary, published_at)
   - Gemini Embedding으로 벡터 변환
5. **클러스터링 및 중복 제거**:
   - DBSCAN으로 유사 뉴스 클러스터링
   - 같은 클러스터 내에서 대표 기사 선택 (최신/가장 긴 본문)
   - 중복 뉴스 제거 후 OpenSearch에 저장

### 5단계: 데이터베이스 모델

**news/models.py 핵심 모델:**

#### 1. News 테이블 (PostgreSQL)

```sql
CREATE TABLE `news` (
    `news_id`       BIGINT          NOT NULL    PRIMARY KEY,
    `title`         VARCHAR(255)    NOT NULL,
    `url`           VARCHAR(500)    NOT NULL    UNIQUE,
    `summary`       TEXT            NULL,
    `published_at`  TIMESTAMP       NULL,
    `created_at`    TIMESTAMP       NOT NULL,
    `updated_at`    TIMESTAMP       NULL,
    `is_deleted`    BOOLEAN         NOT NULL    DEFAULT FALSE
);
```

**필드 설명:**
- `news_id`: 뉴스 고유 ID (Primary Key)
- `title`: 뉴스 제목
- `url`: 원본 링크 (unique, 중복 방지)
- `summary`: Gemini로 생성된 요약문
- `published_at`: 뉴스 발행일 (Naver API에서 추출)
- `created_at`: 레코드 생성 시간
- `updated_at`: 레코드 수정 시간
- `is_deleted`: 소프트 삭제 플래그

**인덱스:**
- `url` (UNIQUE INDEX)
- `published_at` (INDEX)
- `is_deleted` (INDEX)

#### 2. CrawlJob 테이블

**필드:**
- `keywords` (JSON): 검색 키워드 리스트
- `status`: pending/running/completed/failed
- `celery_task_id`: Celery 작업 ID
- `total_articles`: 총 기사 수
- `successful_articles`: 성공한 기사 수
- `failed_articles`: 실패한 기사 수
- `error_message`: 오류 메시지
- `created_at`, `started_at`, `completed_at`

#### 3. OpenSearch 인덱스

```json
{
  "mappings": {
    "properties": {
      "news_id": {"type": "long"},
      "title": {"type": "text"},
      "content": {"type": "text"},
      "content_vector": {
        "type": "knn_vector",
        "dimension": 768
      },
      "published_at": {"type": "date"}
    }
  }
}
```

**필드 설명:**
- `news_id`: PostgreSQL의 news_id와 매핑
- `title`: 검색용 제목
- `content`: 전체 본문 텍스트
- `content_vector`: 벡터 임베딩 (768차원, Gemini text-multilingual-embedding-002)
- `published_at`: 날짜 필터링용

def crawl_news_task(self, job_id, keywords, max_articles_per_keyword=10):

    1. CrawlJob을 running으로 업데이트

       - 각 기사별:
         * URL 중복 체크 (News.url unique 제약)

         * 병렬 처리:
           - SummarizeService로 요약 생성 → PostgreSQL 저장

    3. 클러스터링 및 중복 제거:
       - 모든 임베딩 수집
       - DBSCAN 클러스터링 실행
       - 중복 제거 (대표 기사 선택)
       - 유지할 뉴스만 OpenSearch에 저장
    4. CrawlJob을 completed/failed로 업데이트
    """

## 주의사항

### 1. API 키 관리
- .env 파일에 실제 API 키 입력 필수
- Naver API: https://developers.naver.com/
- Gemini API: https://ai.google.dev/

### 2. API Rate Limit
- Naver API: 초당 10회, 일일 25,000회
- Gemini API: 무료 티어 제한 확인
- 과도한 크롤링 주의

### 3. 성능 고려사항
- Celery concurrency: 2로 제한 (리소스 고려)
- 키워드당 최대 기사 수: 100개 이하 권장
- jina.ai 타임아웃: 30초

### 4. 데이터 중복 처리
- **URL 기반 중복 체크**: News.url에 unique 제약, 중복 기사는 자동으로 스킵
- **의미 기반 중복 제거**: 
  - DBSCAN 클러스터링으로 유사 뉴스 그룹화
  - 같은 클러스터 내에서 대표 기사만 선택 (최신/가장 긴 본문)
  - 중복으로 판단된 뉴스는 OpenSearch에 저장하지 않음
  - PostgreSQL에는 이미 저장되었으므로 soft delete 또는 별도 플래그로 관리 가능

### 5. 에러 처리
- Celery task max_retries=3 설정
- 부분 실패 허용 (일부 기사 실패해도 계속 진행)
- processing_error 필드에 오류 기록

### 6. 모니터링
- Celery Flower 설치 권장: `pip install flower`
- 실행: `celery -A config flower`
- 접속: http://localhost:5555

## 구현 세부사항

### 클러스터링 및 중복 제거 전략

**NewsClusteringService** (`news/utils/clustering.py`):
- **알고리즘**: DBSCAN (Density-Based Spatial Clustering)
- **거리 메트릭**: 코사인 거리 (cosine similarity)
- **파라미터**:
  - `eps=0.1`: 코사인 거리 임계값 (유사도 약 0.9 이상)
  - `min_samples=2`: 하나의 이슈로 묶기 위한 최소 기사 수
- **중복 제거 전략**:
  - `latest`: 가장 최신 기사 선택 (published_at 기준)
  - `longest`: 가장 긴 본문 기사 선택
  - `latest_longest`: 최신 기사 중 가장 긴 본문 선택 (권장)
- **노이즈 처리**: 클러스터에 속하지 않은 기사(-1)는 모두 유지

### 임베딩 모델

- **모델**: `text-multilingual-embedding-002` (Gemini)
- **차원**: 768차원
- **특징**: 다국어 지원, 배치 처리 지원
- **용도**: 의미 기반 검색 및 유사도 계산

### 본문 정제 전략

**RefineService** (`news/services/refiner.py`):
- **1차 정제**: Trafilatura (로컬 라이브러리)
  - 빠른 처리 속도
  - 토큰 절감 (Gemini API 비용 절감)
- **2차 정제**: Gemini AI
  - 광고, 메뉴, 추천 등 불필요한 요소 제거
  - 데이터 순도 보장
- **폴백**: AI 실패 시 로컬 정제본 반환
